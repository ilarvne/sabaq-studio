# Приёмка Sabaq Studio

Этот протокол связывает критерии ТЗ с проверками репозитория и испытаниями на целевом стенде. По каждому пункту сохраните результат, ревизию и артефакт, на котором основан вывод. Промышленная приёмка остаётся открытой. [Запуск и зависимости](../README.md)

## Подготовить набор и стенд

1. Зафиксируйте проверяемый коммит, сборку, версии моделей и обработчиков, настройки стенда, версии браузеров и Office. Для замеров запишите характеристики клиента и сервера. Храните протоколы без ключей доступа и биометрических данных.
2. Утвердите **эталонный набор из 30 презентаций** по восьми предметам. Включите по 10 уроков на казахском, русском и английском языках. Добавьте файлы PPTX, PDF, DOCX и изображения для импорта.
3. Утвердите **расширенную выборку из 100 тем** по восьми предметам до генерации. Включите темы эталона и распределите сгенерированные презентации по языкам в пропорции 40 казахских, 40 русских и 20 английских.

## Измерить быстродействие

На целевом стенде проведите 20 запусков на казахском и 20 на русском при готовых текстовой и графической моделях. Измеряйте время от нажатия до появления результата в интерфейсе. Сохраните сырые замеры, ошибки, число готовых слайдов и изображений, p50 и p90. Отдельно замерьте p90 под нагрузкой на GPU.

| Действие | Цель § 8.1 |
| --- | --- |
| Первый пункт плана и полный план | ≤ 3 / 5 с и ≤ 12 / 20 с по p50 / p90 |
| Первый слайд и комплект из десяти слайдов с пятью или более изображениями | ≤ 10 / 15 с и ≤ 60 / 90 с по p50 / p90 |
| Холодный старт изображений | ≤ 20 с до первого изображения, 10 измерений после простоя не менее 30 минут |
| Одна правка с ИИ и четыре варианта изображения | 50 правок на казахском и русском, ≤ 5 / 8 с по p50 / p90. Для изображений 20 запросов, первый вариант ≤ 6 с и все четыре ≤ 15 с по p90 |
| Редактор с 40 слайдами | Chrome на четырёхъядерном ноутбуке с 8 ГБ памяти. Открытие ≤ 1,5 / 2,5 с, кадр при вводе ≤ 16 / 33 мс по p50 / p90. При вводе нет запросов к серверу, лента прокручивается без пропусков кадров. |
| Смена темы и макета | Тема без изображений ≤ 200 / 400 мс по p50 / p90. Макет ≤ 400 мс по p90. |

Для локального замера открытия, ввода и смены темы соберите приложение и запустите тест на 20 повторах в каждом языке. Строгий режим `STUDIO_BENCHMARK_GATE=1` оценивает пороги теста. Смену макета и поведение на целевом ноутбуке также проверьте вручную. [Сценарий измерения](../tests/editor-performance.spec.ts)

```sh
STUDIO_E2E_BUILT=1 STUDIO_BENCHMARK=1 \
  bun run test:e2e tests/editor-performance.spec.ts
```

## Сохранить результат

`bun run eval:layout` по умолчанию проверяет три перевода встроенного урока. Для расширенной выборки передайте базу и JSON с одной ревизией на презентацию. Каждая запись содержит поля `deck`, `revision` и `subject`. Флаг `--gate` проверяет состав выборки и завершённость измерений, включая все диагностированные проблемы. [Код проверки](../apps/api/tools/evaluate-layout.ts)

```sh
bun run eval:layout --database pilot.sqlite --manifest corpus.json --gate
```

Для каждого требования укажите статус, дату, сборку, идентификатор примера, ожидаемый и фактический результаты. К отчёту приложите доступные логи, кадры, выгрузки и протоколы. Результаты прогонов с заглушками отмечайте отдельно от измерений на целевых сервисах. Для § 8.2 также сопоставьте снимки редактора и кадра до наложения аватара. Допустимо до 0,5 % пикселей с разницей более 8 уровней из 255. Зафиксируйте настройки кадра и режим раскрытия ответа.

## Открытые пункты

- Диалог видео запускает озвучку слайдов. Привязку аватара и согласия к полной пользовательской цепочке, размещение обработчика и фактический выпуск нужно подтвердить в пилоте.
- Проверка числа или текста цитаты по совпадению с выдержкой допускает неверную связь числа с величиной и неверную атрибуцию. Для С2 нужны размеченные примеры с такими перестановками.
- Событие завершения генерации предшествует окончанию проверки макета. Для приёмки оцените сохранённую ревизию после проверки.
- Для ДИЗ-4 подберите 40 тем, по пять на каждый предмет, и проведите отдельную проверку с тремя экспертами. Допустимы два несоответствия темы оформления, отмеченные хотя бы двумя экспертами.
- Для ДИЗ-5 согласуйте проверяемые правила на случай, когда преподаватель запретил изображения или источник не содержит данных для диаграммы.
